DiFingerCapture

Android 지문 캡처 및 매칭을 위한 생체인증 SDK

개요

DiFingerCapture SDK는 DiGentID에서 개발한 Android용 생체인증 SDK입니다.

카메라를 통한 지문 캡처, AI 기반 손가락 감지, 특징점 추출 및 로컬 매칭 기능을 제공합니다. 생체 데이터는 기기 내부에서 처리되며, 지문 원본 이미지 및 특징점은 외부 서버로 전송되지 않습니다. 라이선스 검증 요청에는 라이선스 키, 앱 패키지명, 플랫폼, SDK 버전만 전송됩니다.

주요 기능

  • 실시간 손가락 감지: AI 기반 실시간 손가락 감지 및 품질 분석

  • 자동 캡처: 최적 품질 조건에서 자동으로 지문 이미지 촬영

  • 특징점 추출: 촬영된 지문에서 Minutiae 특징점 추출 (4,096 바이트 고정 버퍼)

  • 로컬 매칭: 추출된 특징점 간 1:1 및 1:N 비교 — 서버 불필요

  • 온디바이스 처리: 생체 데이터가 기기 외부로 전송되지 않음

지원 촬영 모드

기본은 2손가락 동시 촬영(iOS SDK와 동일)입니다. fingerCount = 1을 주면 1손가락 모드로 동작합니다.

등록 (카드A)truegetLocalFingerprintAMultiSlots() — 6개 (R1F1, R1F2, R2F1, R2F2, R3F1, R3F2)getLocalFingerprintARounds() — 3개3회
인증 (카드B)falsegetLocalFingerprintBMulti() — 2개 (F1, F2)getLocalFingerprintB() — 1개1회

2손가락 모드에서 라운드마다 두 손가락이 각각 저장되므로 등록은 6개, 인증은 2개의 특징점이 생깁니다. 매칭은 이 6 × 2 = 12쌍을 모두 비교합니다 (Step 6).

등록과 인증은 같은 fingerCount로 진행해야 합니다. 특징점은 손가락 단위로 저장되므로, 1손가락으로 등록한 지문을 2손가락 인증(또는 그 반대)과 비교할 수 없습니다. iOS SDK도 같은 옵션(fingerCount)과 규칙을 제공합니다.

SDK 사용 전 라이선스 키를 검증합니다. 콜백은 백그라운드 스레드에서 실행됩니다.

LicenseManager.check(this, "YOUR_LICENSE_KEY") { result ->
    runOnUiThread {
        when (result) {
            is LicenseResult.Valid -> {

                Log.w("SDK", "네트워크 오류: ${result.message}")
            }
        }
    }
}

Step 5 — 지문 등록 (카드A, 3라운드 × 2손가락)

class MainActivity : AppCompatActivity() {

    private val enrollLauncher =
        registerForActivityResult(ActivityResultContracts.StartActivityForResult()) { result ->
            if (result.resultCode == RESULT_OK) {
                val pref = UseSharedPreference(this)
                val slots = pref.getLocalFingerprintAMultiSlots()   // 6개: R1F1, R1F2, R2F1, R2F2, R3F1, R3F2

                // 서버 저장 시 6개 모두, 슬롯 순서 그대로 보관 (AES-256 암호화 권장)
            }
        }

    fun startEnrollment() {
        enrollLauncher.launch(
            FingerActivity.createIntent(
                context = this,
                isOriginFingerprint = true,   // 등록 모드
                fingerCount = 2               // 기본값 2 (생략 가능). 1손가락이면 1
            )
        )
    }
}

Step 6 — 지문 인증 (카드B, 1회 × 2손가락) 및 로컬 매칭

등록 6개 × 인증 2개 = 12쌍을 모두 비교하고, 1쌍이라도 매칭되면 성공으로 판정합니다 (iOS SDK multiMatch와 동일한 규칙). multiMatchMinutiae()가 이 비교와 판정을 한 번에 수행합니다.

private val authLauncher =
    registerForActivityResult(ActivityResultContracts.StartActivityForResult()) { result ->
        if (result.resultCode == RESULT_OK) {
            val pref = UseSharedPreference(this)
            val enrolled = pref.getLocalFingerprintAMultiSlots()   // 6개 (등록 시 저장한 순서 그대로)
            val captured = pref.getLocalFingerprintBMulti()        // 2개 (F1, F2)
            if (enrolled.size < 6 || captured.size < 2) return@registerForActivityResult

            lifecycleScope.launch(Dispatchers.IO) {
                val match = IzzixServiceProxy.instance.multiMatchMinutiae(
                    reqFeaturesList = enrolled.map { it.features },
                    resFeaturesList = captured.map { it.features },
                    matchLevel = pref.getMatchLevel(),
                    fingerCount = 2
                )
                // match.isMatch          : 최종 판정 (12쌍 중 1쌍 이상 매칭)
                // match.successCount     : 매칭된 쌍 수 / match.totalComparisons (12)
                // match.bestPair         : 최고 점수 쌍 — reqRound, reqFinger(0=F1,1=F2), score, hitCount, code
                withContext(Dispatchers.Main) {
                    if (match.isMatch) showSuccess() else showFailure()
                }
            }
        }
    }

fun startAuthentication() {
    authLauncher.launch(
        FingerActivity.createIntent(
            context = this,
            isOriginFingerprint = false   // 인증 모드 (fingerCount 기본값 2)
        )
    )
}

오류 처리

LicenseResult

LicenseResult.Valid라이선스 유효SDK 정상 사용
LicenseResult.Invalid키 자체가 무효FingerActivity 진입 차단 필수
LicenseResult.Error네트워크 오류 — 이전 검증 성공 후 24시간 내에는 계속 사용 가능, 그 외에는 SDK 차단(fail-closed)경고 표시, 재시도 권장

라이선스 검증 규칙 (v1.5.x)

  • 서버 응답은 최상위 필드(valid 등)를 신뢰하지 않고, 응답에 포함된 payload/signature(ECDSA P-256 서명)를 SDK 내장 공개키로 검증한 뒤 그 payload 바이트에서만 최종 판정합니다(자체 서버로 위조한 valid: true 응답은 통과 불가).

  • 검증 성공(Valid)은 24시간 동안만 유효합니다. IzzixServiceProxy.instance의 API(extractMinutiae 등)를 호출하려면 그 시점에 LicenseManager.isReady() == true여야 하므로, 앱은 주기적으로(예: 앱 재개 시) LicenseManager.check()를 다시 호출해야 합니다.

  • check()를 한 번도 호출하지 않았거나, 검증이 24시간 넘게 지났거나, 무효 판정을 받은 상태에서 FingerActivity에 진입하면 즉시 종료됩니다. 같은 상태에서 IzzixServiceProxy의 엔진 API를 호출하면 실제 엔진을 실행하지 않고 코드 -953(라이선스 미검증)을 반환합니다.

matchMinutiae 반환값 (MatchResult)

isMatchtrue = 동일인 판정
matchScore매칭 점수 (높을수록 유사)
hitCount매칭에 기여한 특징점 쌍 수
code0 = 정상, 음수 = 엔진/서비스 오류 코드 (IzzixCode로 해석)
reason비매칭 사유 코드 (양수, 매칭 성공 시 0)

multiMatchMinutiae 반환값 (MultiMatchResult, v1.5.3)

isMatch최종 판정 — 비교 쌍 중 1쌍이라도 매칭되면 true
successCount / totalComparisons매칭된 쌍 수 / 비교한 쌍 수 (2손가락: 6 × 2 = 12)
matchedPairs매칭에 성공한 쌍 목록 (MatchedPair)
allComparisons모든 쌍의 결과 — 실패·엔진 오류(code < 0) 포함
bestPair점수가 가장 높은 쌍 — reqRound(1~3), reqFinger(0 = F1, 1 = F2), score, hitCount

extractMinutiae / getMinutiae 반환값 (v1.5.0 변경)

  • extractMinutiae는 항상 ExtractResult를 반환합니다(null 아님). 실패 여부는 code < 0으로 판정하고, reason/IzzixCode.fromCode(code)로 사유를 확인합니다.

  • getMinutiae는 MinutiaeResult를 반환합니다. 특징점 목록은 points, 성공 여부는 code >= 0입니다.

  • 마지막 호출의 진단 정보는 IzzixServiceProxy.instance.lastCode / lastDiag로 조회할 수 있습니다.
